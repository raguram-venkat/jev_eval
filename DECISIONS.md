# Decisions

One line per non-obvious choice, with the reason.

## Sprint 1

- The package is `jev_eval` (`module-name = "jev_eval"` in `[tool.uv.build-backend]`, matching the `src/jev_eval` directory), while the console script and CLI prog name are the hyphenated `jev-eval`, since hyphens aren't valid in a Python module name but are the normal CLI convention.
- `datasets` moved to a dev dependency group: only `prep_data.py` needs it, the benchmark itself doesn't. The unused `pytorch-cpu` index is removed (no torch anywhere in this project).
- `Config.api_key` is `field(repr=False)` and `__repr__`/`__str__` are overridden to print only `base_url`; the `Authorization` header is built on demand by `auth_headers()` and never stored on the object, so no dump of a config can leak the key.
- The key is `.strip()`ped; a whitespace-only key counts as unset (catches a trailing newline from `export KEY=$(cat file)`).
- Argparse usage errors (`--limit`, `--experiments`) exit 2 before the key is even read; a missing key also exits 2 via `parser.exit`. A frozen-data failure exits 1, naming the offending file.
- Frozen data is verified with `hashlib.file_digest` over files opened `rb` only; nothing under `data/frozen/` is ever opened for writing (tested by spying on `Path.open`).
- `protocol/questions.py` is hashed as raw file bytes, so any edit to instructions, criteria or state builders changes `questions_hash()`. Question text must never change in response to results.
- Yelp Score levels are 0-based on the wire (level i is i + 1 stars); the five level texts are fixed before any results exist.
- Banking77 criteria are label-name-only (`{opt: opt}`), a deliberate zero-shot choice, called out as a caveat later in the report.
- `tests/conftest.py` blocks non-loopback network access via `pytest.fail` (a `BaseException`), so a retry loop that catches `Exception` can't hide an accidental live call.

## Sprint 2

- **Cache key / model-version scheme:** the key is `sha256(requested_model + "\n" + canonical_body)`, where `requested_model` is the request's own `model` field (e.g. `jev-latest`) and `canonical_body` is `json.dumps(body, sort_keys=True, separators=(',',':'))`. The *returned* version isn't known until a response arrives, so it can't be part of the key — instead every entry stores it, and every response (live or cached) feeds the run's model-version guard, so a stale entry from another version aborts the run instead of silently mixing versions.
- Cache entries hold only `key`, `requested_model`, `model`, `latency_ms` and the response — never headers or the request body. Writes are temp-file-then-`os.replace` so a reader never sees a half-written file; an unreadable or malformed entry is treated as a miss, not an error.
- `--no-cache` builds the client with `cache=None`, so `cache/` is never even created, let alone read or written.
- Retry: 429, 5xx and `httpx.TransportError` retry up to 5 attempts with `min(2**(attempt-1), 30)` s backoff plus jitter (0-1s, both injectable so tests never wait); `Retry-After` (seconds form only) replaces the backoff base, capped at 60s so a hostile header can't stall a run. 401/403 raise `AuthError` on the first attempt with no retry — retrying an auth failure wastes 4 attempts on something that will never succeed.
- One `threading.Lock` inside `RunContext` guards the sent counter, the model-version guard and the per-experiment failure counts. `reserve()` checks the guard *before* every attempt, so once a model change is recorded no thread starts a new request — only requests already in flight can still land, and their models are still recorded.
- Preflight (`GET /v1/models`) never retries: retrying a broken endpoint for ~15s before telling the user helps nobody. Any non-200 or connection error exits `run` with 1, naming the URL and status/exception type but never the key.

## Sprint 3

- The `/v1/systemone` wire format (learned from docs.typesafe.ai, not in PREMISE.md) is `{"state": ..., "model": ..., "questions": {qid: {"type": ..., "instructions": ..., "criteria": ...}}}`. Response answers are keyed by the same `qid`; Choice returns `choice`/`probabilities`/`confidence`, Noul returns a single `noul` (p(yes), no separate confidence), Score returns `score`/`probabilities`/`confidence`/`legend`, with probability keys and `score` itself 0-based on the wire.
- Question ids (`intent`, `answer`, `stars`) live in `protocol/questions.py` next to the builders that use them, so a runner never hardcodes a magic string to index into a response.
- Fixtures (`tests/fixtures/*_request.json`, `*_response.json`) are captured live via `./capture_fixtures.sh` against the real API — not hand-written — so parser tests are checked against a shape Jev actually returns. `capture_fixtures.sh` is safe to rerun; it only ever appends fresh captures.
- Score's exact-level accuracy uses the argmax over `probabilities` (the model's most likely level), not `round(score)`; MAE uses `score + 1` on the 1..5 stars scale. Both derive from probabilities/score, never from `confidence`.
- `--limit N` for E1 is stratified by round-robin across every `(k, draw)` group in sorted order, taking one row per group per round — so even `--limit 10` (fewer than the 10 groups) still touches every condition once it can, and the same `--limit` always picks the same rows.
- `run_experiment()` in `experiments/runner.py` is dataset-agnostic: it takes rows plus a `request_fn`/`parse_fn` pair and knows nothing about Banking77 specifically. E2/E3 (next sprint) reuse it unchanged; only `experiments/e1.py`'s dataset-specific twin needs writing.
- If `RunContext` raises `ModelChangedError` or `RequestCapError` mid-run, `run` reports the error and exits 1 without writing `predictions.jsonl` for that invocation — no partial-run manifest yet. Abort-path manifests (a `manifest.json` with an `aborted` reason) are deferred to the plots/report sprint, where the acceptance criteria actually require them.

## Sprint 4

- Stratified `--limit` sampling moved out of `experiments/e1.py` into a shared `experiments/sampling.py`: each dataset module supplies its own `group_key` (banking77: `(k, draw)`, boolq: `label`, yelp: `stars`) over the same round-robin algorithm, so `--limit 20` on E2 still gets a balanced yes/no subset and E3 still touches every star rating.
- E5 (latency) gets its own `RunContext` wrapping a client built with `cache=None`, independent of the main run's cached client and `--no-cache` flag — latency numbers must reflect a real round trip every time, and this is the only experiment where that's true regardless of what the user passed. This also means E5's request cap and model-version guard are scoped to E5 alone, not shared with whatever ran before it in the same invocation; still fine at E5's volumes (a few hundred requests, cap is 4000).
- E5's "5 independent questions" test reuses one Banking77 row's choice question, repeated under keys `q0`..`q4` against the same `state` — it's the same question asked 5 times in parallel, not 5 different questions, since the point is measuring the cost of batching, not accuracy.
- Noul predictions store `confidence: None`: the wire format has no separate confidence field for Noul (unlike Choice/Score), the `noul` probability *is* the whole distribution.
- **Bug caught before it did real damage:** a sprint-3 CLI test ran `e2,e3,e4,e5` against a fake server with no `/v1/systemone` responder configured, which used to be harmless when e2/e3 didn't exist yet — but once this sprint registered them, that test actually executed them, and because it didn't pass `--no-cache` it wrote 600 garbage entries into the real repo's `cache/` directory (the client caches any structurally-valid 200 response with a `model` field, even one that later fails to parse). Fixed by an autouse fixture in `tests/test_cli.py` that always points `CACHE_DIR`/`RESULTS_DIR` at `tmp_path` — no CLI test may touch the real `cache/` or `results/` again.

## Sprint 5

- `predictions.jsonl` rows aren't tagged with which experiment produced them; `analysis/summary.py` buckets them by id prefix instead (`b77-`/`boolq-`/`yelp-`), since the prefix is already a reliable, existing discriminator and adding a redundant field would just be another thing to keep in sync.
- `choice_brier`/`choice_ece` sum over **each row's own** probability dict rather than a shared label list — Banking77 rows pooled across draws (even at the same k) can have completely different option subsets, so there's no single shared label space to score against.
- Score's continuous prediction isn't stored separately in `predictions.jsonl` — it's recovered in `analysis/summary.py` as `sum(stars * p)` over the saved probabilities, which is mathematically identical to the wire's own `score` (a probability-weighted mean of levels): storing it twice would just be a field that can drift from the data it's derived from.
- `metrics.bootstrap_ci` (`analysis/metrics.py`) is one generic case-resampling helper (fixed seed 1729, 1000 resamples) that every metric closes over with its own `stat_fn`, rather than a bespoke CI routine per metric — new metrics get a CI for free.
- E4 (selective prediction) sends no requests: `analysis/summary.py` derives it entirely from whatever E1 (k=20, 77) and E2 predictions already exist in the same run's `predictions.jsonl`, exactly per PREMISE.md. Both are absent when a run doesn't include those experiments, which just means no E4 row that run — not an error.
- `jev-eval summarize <run_dir>` re-derives `summary.csv` from an existing `predictions.jsonl`/`latency_samples.jsonl` with no config, no client and no network — matches the PREMISE.md requirement directly, and `run` also calls it automatically at the end of a live run.
- Live at `--limit 30` across e1-e5: E1 accuracy stayed at 1.0 through k=20 and dropped to 0.67 at k=77 (n=3, wide CI); E2 (BoolQ) hit 0.97 accuracy against a 0.5 baseline; E3 (Yelp) MAE 0.25 against a baseline of 1.2; E4 coverage@90/95 was 1.0 for k=20 and E2, 0.67 for k=77; E5's 5-question p50 (337ms) came in *under* the 1-question p50 (409ms) — no sign yet that batching questions costs more.

## Sprint 6

- PREMISE.md's Outputs section names exactly **seven** plot files; its acceptance criterion 5 says "nine" without ever naming two more anywhere in the document. Treated as a slip in the spec, not two undocumented plots — `analysis/plots.py` produces the seven that are actually named and described.
- Every plot function degrades gracefully on missing data instead of crashing (a genuinely useful property caught by a real test failure this sprint: `plot_label_sweep` used a log-scale x-axis unconditionally and crashed with "Data cannot be log-scaled" the moment a run had zero E1 predictions). Empty inputs now draw a "no data" placeholder and the file still gets written, so a partial `--experiments` run never breaks the plot step for the experiments it did run.
- `RunContext.run()` can raise `AuthError` (401/403), not just `ModelChangedError`/`RequestCapError` — `cli.py`'s abort handling now catches all three (`ABORT_ERRORS`). Previously only the latter two were caught, so a live auth failure mid-run would have crashed with a raw traceback instead of exiting cleanly; caught by adding an abort-manifest test for a 401 mid-run before ever hitting it live.
- On abort, `run` still writes whatever `predictions.jsonl`/`latency_samples.jsonl` was collected before the failure, plus a `manifest.json` with an `aborted` reason — but never `summary.csv`, `plots/` or `REPORT.md`, so a partial run can never look like a finished one.
- `REPORT.md`'s "Where Jev fails" section says so explicitly, with a count, when fewer than 10 misclassified examples exist, rather than padding the table — matches the acceptance criterion instead of silently producing a short table.

## Sprint 9

- `src/jev_eval/` was flat (22 files in one directory) and got split into four subpackages by concern: `protocol/` (the wire format — `questions.py`, `parsers.py`), `client/` (talking to Jev — `http.py`, `cache.py`, `runctx.py`), `experiments/` (one module per dataset plus the shared `runner.py`/`sampling.py`), `analysis/` (deriving numbers from predictions already on disk — `metrics.py`, `baselines.py`, `summary.py`, `plots.py`, `report.py`). `cli.py`, `config.py`, `frozen.py`, `results.py` and `capture_fixtures.py` stayed at the top level — each is either the orchestrator or small and foundational enough that a subpackage would be ceremony, not clarity.
- `client.py` became `client/http.py`, not `client/client.py` — a submodule can't share its parent package's name, and "http" names what the file actually does (the HTTP layer) rather than restating the package.
- No `__init__.py` re-exports anywhere: every cross-module import names the exact submodule it needs (`from jev_eval.client.http import JevClient`, not `from jev_eval.client import JevClient`). One consistent import style everywhere beats a shorter path in some packages and not others, and it means a reader never has to go check an `__init__.py` to find out where something actually lives.
- `results.py` (writing predictions/manifest/latest) stayed out of `analysis/` on purpose: `analysis/*` is strictly "derive insight from a predictions.jsonl already on disk" — used identically by a live `run` and by offline `jev-eval summarize` — while `results.py` is "what a live run writes," orchestrated directly by `cli.py` and used nowhere else.
- Every markdown reference to a moved file (`DECISIONS.md` itself, `INDEX.md`, `sprints/*.md`) was updated to its new path rather than left as a historical snapshot — a decision log you can't navigate with the current tree isn't worth much more than no log at all.

## Sprint 11

- `analysis/summary.py` and `analysis/plots.py` scored Choice's calibration (ECE, E1) and selective-prediction gate (E4, Banking77 conditions) against `max(probabilities)`, not the `confidence` field Choice and Score actually return alongside `probabilities` on the wire. That's backwards for a metric whose entire job is "is Jev's stated confidence trustworthy" — it was silently substituting a different, always-internally-consistent-by-construction number for the one actually being graded, so a model that's well-calibrated on `max(probabilities)` but garbage on its own `confidence` field would have looked fine here. Fixed by sourcing `confidence` from `predictions.jsonl`'s own `confidence` field for both; `metrics.choice_ece`'s parameter was renamed `max_probs` → `confidence` to match. Noul (BoolQ) is unchanged — it has no separate `confidence` field on the wire (Sprint 4), so `p_yes`/`max(probabilities)` stays the only signal there ever was, not a stand-in for something better.
- Re-running `jev-eval summarize` + `report.write_report` + `plots.generate_all` against the existing `results/20260930T185023Z/predictions.jsonl` (no new API calls, same stored data) moved E1's ECE down at every k except k=77 (k=20: 0.062→0.049; k=77: 0.096→0.094) and E4's `e1_k=77` coverage_at_95 down (0.607→0.567); `coverage_at_90` for both k=20 and k=77, and everything for E2/BoolQ, came out identical — confidence and max(probabilities) agree closely enough on this run that only the finer-grained numbers moved, not the headline ones.
- `tests/test_cli.py`'s fake-server fixture for the E1 end-to-end test didn't include a `confidence` field on its echoed `choice` answer, which crashed `choice_ece` once it stopped falling back to `max(probabilities)`. Fixed the fixture to include `confidence` (a real Choice response always has one), not the production code — a `None` confidence on a real Choice/Score answer would be a wire-contract violation, not a case to handle gracefully.
